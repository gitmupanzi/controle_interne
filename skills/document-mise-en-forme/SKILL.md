# Skill — Mise en forme documentaire IMF Bisou Bisou

## 0. Rôle du skill

Ce skill définit les règles obligatoires de présentation, de mise en forme, de structuration, de contrôle qualité et de finalisation des documents produits dans le cadre de la **Microfinance BISOU BISOU S.A**.

Il s'applique aux formats suivants :

- **Word** : `.docx`, `.dotx`
- **Excel** : `.xlsx`, `.xlsm`
- **PDF** : `.pdf`

Ce skill est transversal au projet IMF BB.

Il doit être appliqué à tout livrable institutionnel, administratif, opérationnel, analytique, financier, Data ou IT, sauf instruction explicite contraire.

L'objectif est qu'un document IMF BB soit immédiatement reconnaissable par :

- sa sobriété ;
- sa cohérence visuelle ;
- sa lisibilité ;
- sa qualité professionnelle ;
- son identité institutionnelle ;
- la fiabilité de sa présentation ;
- la facilité d'exploitation de l'information ;
- la cohérence de sa structure.

---

# 1. Principes communs à tous les formats

## 1.1. Identité institutionnelle

Nom officiel :

**Microfinance BISOU BISOU S.A**

Ne pas remplacer ce nom par simplement **Bisou Bisou** dans un document institutionnel ou externe, sauf lorsque le contenu métier l'exige explicitement.

Le logo officiel doit être utilisé lorsqu'un document nécessite une identité institutionnelle.

Le logo doit provenir d'un asset officiel fourni dans le projet ou par l'utilisateur.

Ne jamais :

- recréer approximativement le logo ;
- modifier arbitrairement ses couleurs ;
- l'étirer ou le déformer ;
- utiliser une version trouvée sur Internet lorsqu'un asset officiel existe.

## 1.2. Fidélité au contenu

Lorsqu'une demande concerne uniquement la mise en forme :

- ne pas modifier les chiffres ;
- ne pas modifier les dates ;
- ne pas modifier les noms ;
- ne pas modifier les conclusions ;
- ne pas supprimer de contenu métier ;
- ne pas inventer de données ;
- ne pas modifier le sens d'une recommandation ;
- ne pas transformer un résultat analytique sans instruction explicite.

La mise en forme ne doit jamais altérer la donnée.

## 1.3. Sobriété

Éviter :

- les couleurs excessives ;
- les polices fantaisie ;
- les effets 3D ;
- les WordArt ;
- les ombres lourdes ;
- les décorations inutiles ;
- les arrière-plans chargés ;
- les icônes sans fonction ;
- les mises en page trop denses.

La priorité est donnée à la clarté de l'information.

## 1.4. Police institutionnelle

Police principale :

**Aptos**

Utiliser Aptos autant que possible dans Word, Excel et les documents destinés à être exportés en PDF.

## 1.5. Formats de données

### Montants

Exemples :

**1 250,00 USD**

**3 500 000 CDF**

Utiliser un espace comme séparateur de milliers.

### Pourcentages

Exemple :

**12,50 %**

### Dates

Format institutionnel :

**07 août 2026**

Format technique acceptable dans les tableaux :

**07/08/2026**

Le format doit rester cohérent dans un même livrable.

## 1.6. Confidentialité

Niveaux recommandés :

- Interne
- Confidentiel
- Diffusion restreinte
- Externe

Pour les documents sensibles :

**CONFIDENTIEL – USAGE INTERNE**

Sont notamment considérées comme sensibles :

- données clients ;
- informations financières individuelles ;
- résultats de contrôle ;
- anomalies ;
- incidents ;
- données de sécurité ;
- informations stratégiques ;
- informations techniques sensibles.

# 3. Mise en forme Word

## 3.1. Format

Format papier par défaut :

**A4**

Orientation :

- Portrait par défaut ;
- Paysage pour les tableaux larges ou matrices.

Une section spécifique peut être mise en paysage sans basculer tout le document.

## 3.2. Marges

- Gauche : 2,5 cm
- Droite : 2 cm
- Haut : 2 cm
- Bas : 2 cm

## 3.3. Typographie

- Texte normal : Aptos 11 pt
- Titre du document : Aptos 18 pt, gras
- Titre niveau 1 : Aptos 14 pt, gras
- Titre niveau 2 : Aptos 12 pt, gras
- Titre niveau 3 : Aptos 11 pt, gras

## 3.4. Paragraphes

- Interligne : 1,15
- Espacement après : 6 pt
- Rapports : texte justifié
- Listes : alignement gauche
- Éviter les paragraphes inutilement longs

## 3.5. Hiérarchie des titres

Utiliser au maximum trois niveaux principaux :

- Titre 1
- Titre 2
- Titre 3

Structure attendue :

1. Titre principal
1.1. Sous-titre
1.1.1. Niveau inférieur

Éviter les structures trop profondes.

# 4. Numérotation automatique Word

## 4.1. Principe obligatoire

La numérotation des titres doit être **automatique**.

Ne jamais saisir manuellement les numéros des titres lorsqu'une numérotation automatique Word peut être utilisée.

Utiliser les listes à plusieurs niveaux natives de Word et les associer aux styles :

- **Titre 1** → 1., 2., 3.
- **Titre 2** → 1.1., 1.2., 1.3.
- **Titre 3** → 1.1.1., 1.1.2., 1.1.3.

Exemple :

1. Introduction
2. Analyse des clients
   2.1. Clients actifs
   2.2. Nouveaux clients
   2.3. Clients avec DAT
3. Analyse des crédits
4. Recommandations

La numérotation doit se mettre à jour automatiquement lorsqu'une section :

- est ajoutée ;
- est supprimée ;
- est déplacée ;
- change de niveau.

## 4.2. Listes numérotées

Pour les étapes, procédures ou actions ordonnées, utiliser une liste numérotée automatique.

Exemple :

1. Importer le fichier.
2. Vérifier la période.
3. Contrôler les colonnes.
4. Générer le rapport.

Ne pas taper manuellement :

`1.`
`2.`
`3.`

si Word peut gérer la numérotation automatiquement.

## 4.3. Continuité des numéros

Vérifier :

- la continuité des numéros ;
- les niveaux ;
- les retraits ;
- l'alignement ;
- la reprise correcte après une interruption.

Ne pas recommencer automatiquement à 1 lorsqu'une liste doit continuer.

Recommencer à 1 uniquement lorsqu'il s'agit réellement d'une nouvelle liste.

## 4.4. Sous-listes

Utiliser les niveaux natifs de Word pour les sous-listes.

Exemple :

1. Importation
   1.1. Vérification du fichier
   1.2. Contrôle de la période
2. Analyse
   2.1. Épargne
   2.2. Crédit

Ne pas simuler les niveaux avec des espaces ou des tabulations manuelles.

# 5. Puces Word

## 5.1. Principe

Pour une liste sans ordre logique, utiliser les puces natives de Word.

Exemple :

- Clients actifs
- Nouveaux clients
- Clients avec DAT
- Clients avec mouvements

## 5.2. Sous-niveaux

Utiliser les niveaux natifs de Word.

Exemple :

- Clients
  - Clients actifs
  - Clients inactifs
- Produits
  - Épargne
  - Crédit
  - DAT

## 5.3. Choix entre puces et numérotation

Utiliser une liste numérotée lorsque :

- l'ordre est important ;
- il s'agit d'étapes ;
- il s'agit d'une procédure ;
- les éléments doivent être référencés ;
- la séquence doit être respectée.

Utiliser des puces lorsque :

- l'ordre n'est pas important ;
- il s'agit d'exemples ;
- il s'agit de caractéristiques ;
- il s'agit d'une liste simple ;
- il s'agit d'éléments de même niveau.

## 5.4. Interdictions

Ne pas saisir manuellement les caractères suivants pour simuler une liste lorsque Word peut créer une vraie liste :

- `•`
- `-`
- `*`
- `>`

Ne pas créer une liste avec des espaces ou tabulations manuelles.

## 5.5. Cohérence

Dans une même section, conserver :

- le même type de puce ;
- le même retrait ;
- le même espacement ;
- le même niveau visuel.

Éviter de mélanger plusieurs styles de puces sans raison.

# 12. Mise en forme Excel

## 12.1. Objectif

Un fichier Excel IMF BB doit rester :

- lisible ;
- filtrable ;
- exploitable ;
- imprimable ;
- compatible avec l'analyse ;
- compréhensible par un utilisateur non technique.

La mise en forme ne doit jamais empêcher l'exploitation des données.

## 12.2. Structure du classeur

Donner des noms explicites aux feuilles.

Exemples :

- Synthèse
- Clients
- Épargne
- Crédit
- DAT
- M_Pesa
- Contrôles
- Paramètres
- Sources

Éviter :

- Feuil1
- Sheet1
- Copie de Feuil1

sauf si le fichier source doit être conservé tel quel.

## 12.3. Ligne d'en-tête

La ligne d'en-tête d'un tableau doit :

- être en gras ;
- être clairement distincte des données ;
- être figée lorsque le tableau est long ;
- avoir les filtres activés lorsque pertinent ;
- ne pas contenir de cellule vide entre les colonnes utilisées.

## 12.4. Noms des colonnes — Data / IT

Pour les tableaux techniques, conserver la convention avec `_`.

Exemples :

- ID_Client
- Nom_Client
- Montant_Crédit
- Date_Décaissement
- Solde_DAT
- Statut_Client
- Date_Dernière_Opération
- Code_Devise

Règles :

- conserver `_` ;
- accents français autorisés ;
- première lettre en majuscule possible ;
- ne pas modifier arbitrairement les noms provenant des sources ;
- conserver les colonnes nécessaires à la traçabilité.

## 12.5. Noms des colonnes — Direction / externe

Utiliser des libellés naturels :

- ID client
- Nom du client
- Montant crédit
- Date de décaissement
- Solde DAT
- Statut client
- Date de dernière opération
- Devise

## 12.6. Largeur des colonnes

Adapter la largeur au contenu.

Éviter :

- les colonnes excessivement larges ;
- les textes coupés sans raison ;
- les colonnes trop étroites montrant `#####`.

Utiliser le retour à la ligne dans les en-têtes lorsque nécessaire.

## 12.7. Alignement

- texte : gauche ;
- identifiants : gauche ou centre ;
- nombres : droite ;
- montants : droite ;
- pourcentages : droite ;
- dates : centre ou droite.

## 12.8. Formats numériques

Les cellules contenant des nombres doivent rester numériques.

Ne pas convertir inutilement :

- montants ;
- pourcentages ;
- dates ;
- quantités

en texte uniquement pour améliorer l'affichage.

L'affichage doit être obtenu avec les formats de cellules.

## 12.9. Tableaux structurés

Lorsque pertinent, utiliser les tableaux Excel structurés.

Avantages :

- filtres ;
- tri ;
- formules structurées ;
- extension automatique ;
- meilleure lisibilité.

## 12.10. Volets figés

Pour un tableau long :

- figer la ligne d'en-tête ;
- figer éventuellement les premières colonnes d'identification.

Exemple :

ID_Client + Nom_Client visibles pendant le défilement.

## 12.11. Couleurs

Utiliser les couleurs avec modération.

Elles peuvent servir à distinguer :

- en-têtes ;
- zones de saisie ;
- résultats ;
- alertes ;
- totaux ;
- KPI.

Ne pas utiliser uniquement la couleur pour transmettre une information importante.

## 12.12. Mise en forme conditionnelle

Autorisé pour :

- dépassement de seuil ;
- anomalie ;
- retard ;
- statut ;
- comparaison à une cible ;
- doublon ;
- valeur manquante.

La règle doit rester compréhensible.

Éviter les mises en forme conditionnelles excessives.

## 12.13. Numérotation Excel

Lorsque le tableau contient une colonne de type :

- N°
- Rang
- Ordre
- Numéro_Ligne

et que la numérotation doit évoluer avec les données, privilégier :

- une formule ;
- un tableau structuré ;
- une logique dynamique ;
- Power Query lorsque pertinent.

Ne pas saisir manuellement des centaines de numéros si une numérotation automatique est possible.

Les identifiants métier tels que :

- ID_Client
- ID_Compte
- ID_Opération
- Numéro_Dossier

ne doivent jamais être recalculés ou remplacés par une numérotation artificielle.

## 12.14. Puces dans Excel

Les puces ne doivent pas être utilisées dans les tableaux de données structurées.

Elles sont autorisées dans :

- feuilles de synthèse ;
- notes ;
- instructions ;
- commentaires ;
- zones explicatives.

Dans un tableau de données, chaque information doit rester dans une cellule structurée.

## 12.15. KPI Excel

Pour une feuille Synthèse :

- nom du KPI ;
- valeur ;
- période ;
- unité ;
- comparaison ;
- objectif si disponible ;
- commentaire court.

Exemple :

| Indicateur | Valeur | Période | Évolution |
|---|---:|---|---:|
| Clients actifs | 1 245 | Juillet 2026 | +8,4 % |
| Encours crédit | 428 500 USD | 31/07/2026 | +2,1 % |

## 12.16. Graphiques Excel

Utiliser des graphiques simples.

Préférer :

- courbe : évolution dans le temps ;
- barres : comparaison ;
- barres horizontales : catégories longues ;
- histogramme : distribution ;
- camembert : uniquement pour quelques catégories simples.

Éviter :

- 3D ;
- fonds chargés ;
- trop de séries ;
- légendes inutiles.

Chaque graphique doit comporter :

- un titre ;
- la période ;
- l'unité lorsque nécessaire.

## 12.17. Formules

Ne pas remplacer une formule dynamique par une valeur fixe si le fichier doit rester vivant.

Protéger la logique du classeur.

Ne pas casser :

- formules ;
- tableaux structurés ;
- TCD ;
- Power Query ;
- relations ;
- macros ;
- validations de données.

## 12.18. Impression Excel

Lorsqu'un fichier est destiné à être imprimé ou exporté en PDF :

- définir la zone d'impression ;
- répéter la ligne d'en-tête sur chaque page ;
- vérifier les sauts de page ;
- utiliser Portrait ou Paysage selon le tableau ;
- ajuster à une largeur raisonnable ;
- éviter les pages contenant seulement une ou deux colonnes ;
- ajouter en-tête et pied de page si nécessaire.

# 13. Mise en forme PDF

## 13.1. Principe

Le PDF est considéré comme un format final de diffusion.

Il doit être produit à partir d'un document Word, Excel ou d'une autre source déjà correctement mise en forme.

Le PDF doit conserver :

- l'identité IMF BB ;
- les polices ;
- les tableaux ;
- les graphiques ;
- les images ;
- les sauts de page ;
- les marges ;
- les numéros de page ;
- les puces ;
- les listes numérotées ;
- la hiérarchie des titres.

## 13.2. Format

Format privilégié :

**A4**

L'orientation doit suivre celle du document source.

## 13.3. Lisibilité

Avant livraison :

- aucun texte ne doit être coupé ;
- aucun tableau ne doit dépasser la page ;
- aucun graphique ne doit être tronqué ;
- aucune image ne doit être déformée ;
- aucune page blanche accidentelle ne doit apparaître ;
- aucune ligne ne doit se superposer au pied de page.

## 13.4. Pagination

Pour les rapports de plusieurs pages :

**Page X sur Y**

La pagination doit correspondre réellement au fichier final.

## 13.5. Numérotation et puces dans le PDF

Le PDF doit conserver fidèlement :

- la numérotation automatique des titres ;
- les listes numérotées ;
- les puces ;
- les niveaux de listes ;
- les retraits ;
- la continuité des numéros.

Ne pas reconstruire manuellement les numéros dans le PDF après conversion.

La source Word ou Excel doit être corrigée avant export si la numérotation est incorrecte.

## 13.6. Signets

Pour les documents PDF longs, utiliser des signets lorsque possible.

Ils doivent correspondre aux grandes sections du document.

## 13.7. Liens

Les liens internes ou externes doivent rester actifs lorsque le contexte le permet.

## 13.8. Tableaux dans les PDF

Un tableau doit être lisible à une taille d'affichage normale.

Si un tableau est trop large :

- utiliser une page paysage ;
- réduire raisonnablement la police ;
- répartir le tableau ;
- placer les détails en annexe.

Ne jamais générer un PDF dont les colonnes sont coupées hors page.

## 13.9. PDF issu d'Excel

Avant export :

- vérifier la zone d'impression ;
- vérifier les sauts de page ;
- vérifier l'orientation ;
- répéter les en-têtes ;
- vérifier que les colonnes importantes restent sur la même page ;
- éviter l'option de réduction qui rend le texte illisible.

## 13.10. PDF issu de Word

Avant export :

- mettre à jour la table des matières ;
- mettre à jour les champs ;
- mettre à jour les numérotations ;
- vérifier les numéros de page ;
- vérifier les en-têtes et pieds de page ;
- vérifier les sections Portrait/Paysage ;
- vérifier les légendes ;
- vérifier les tableaux multipages ;
- vérifier les puces et listes à plusieurs niveaux.

## 13.11. Confidentialité du PDF

Si le contenu est sensible, afficher clairement :

**CONFIDENTIEL – USAGE INTERNE**

Ne pas supposer qu'un PDF est sécurisé simplement parce qu'il est difficile à modifier.

- chiffres ;
- dates ;
- noms ;
- périodes ;
- confidentialité ;
- absence de données inventées ;
- absence de contenu coupé ;
- cohérence des listes ;
- cohérence de la numérotation.

## 16.2. Contrôles Word

Vérifier :

- format A4 ;
- marges ;
- styles ;
- titres ;
- numérotation automatique ;
- listes numérotées ;
- puces ;
- continuité des listes ;
- niveaux de titres ;

- tableaux multipages ;
- sections paysage ;
- page de garde ;

- en-tête ;
- pied de page ;

## 16.3. Contrôles Excel

- noms des feuilles ;
- filtres ;
- volets figés ;
- formats de cellules ;
- formules ;
- colonnes ;

- tableaux ;
- graphiques ;

8. utiliser la numérotation automatique lorsque nécessaire ;
9. utiliser les listes à puces natives lorsqu'elles sont appropriées ;
10. ne pas simuler manuellement une liste automatique ;
11. vérifier la continuité des numéros ;
12. vérifier les niveaux de titres ;
13. vérifier la lisibilité des tableaux ;
14. vérifier les données chiffrées ;
15. vérifier visuellement le rendu final ;
16. corriger les problèmes détectés avant livraison.

Pour Excel, l'agent doit en plus préserver autant que possible :

- formules ;
- types de données ;
- tableaux ;
- filtres ;
- TCD ;
- Power Query ;
- macros ;
- validations ;
- logique existante.

- la période ;

- les données importantes ;
- les KPI ;
